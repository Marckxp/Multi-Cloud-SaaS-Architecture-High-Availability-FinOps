# How this repository works

This showcase is not edited like an ordinary repository. Its data comes from a sanitized fact package, and CI decides what may be published.

1. The private project generates a sanitized fact package (`facts/state.json` and `facts/decisions/`). A local verifier runs before the push.
2. The package comes in through a pull request with the `facts-package` label. CI blocks identifiers (GUID, OCID, IP, email, provider hostnames, keys) and a list of forbidden terms that lives in a secret, never in the repository.
3. The same PR carries the README data blocks, the complete lists of `docs/engineering.md` and the ADRs with their index, generated by script from the facts and checked in CI. The cycle ends at its merge. The free text changes only when someone edits it, following [`AGENTS.md`](../AGENTS.md), and that PR goes through the same CI.

## The checks

| Check | What it does |
|---|---|
| `verificar` | Validates the facts against the schema, checks that the generated files are up to date, scans for identifiers and for the forbidden terms, and limits which paths a facts PR may touch |
| `revisao` | Deterministic rules for the free text, the quality gate and a semantic review, for PRs that come from an agent |
| SonarQube Cloud | Quality gate on every pull request |

## Tools

| Path | Contents |
|---|---|
| `tools/verify-facts.mjs` | Validates `facts/state.json` against `facts/state.schema.json` |
| `tools/generate-readme.mjs` | Generates the data blocks of the README and of `docs/engineering.md` |
| `tools/generate-adrs.mjs` | Generates `docs/adr/` and its index from `facts/decisions/` |
| `tools/check-leaks.mjs` | Blocks identifiers and forbidden terms |
| `tools/review-text.mjs` | Deterministic rules for the free text |

The scripts have no dependencies. There is no `npm install`.
